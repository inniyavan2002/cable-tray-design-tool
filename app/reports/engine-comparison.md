# Engine comparison: new sizing engine vs tool.html

Generated by `npm run compare` from 1000 seeded random trays built from real catalog cable ODs
(400 one-layer, 350 two-layer, 250 three-layer).
Settings vary per tray: spacing 0/0.5/1/2d, layer gap on/off, clearance factor 0.3/0.5/1, top clearance 0/10/20%,
spare 0/20/25%, max fill 40/50%. Standard sizes are the defaults (widths 50–1000 mm, heights 25–200 mm).
"Legacy" is a verbatim copy of `computeTray()` from `tool.html` at commit b56bb36.

Multi-layer trays are kept small (up to 12 cables) because the legacy engine takes seconds on larger ones.

## Summary

| Comparison | Trays | Meaning |

| Larger cross-section than today | 240 | Caused by clearance on both sides or by fill upsizing (see below) |
| Smaller cross-section than today | 125 | Caused by the new layer arrangement |
| Same cross-section, different shape | 11 | For example 300 × 150 instead of 450 × 100 |
| Legacy showed FAIL (fill over limit) | 23 | The new engine never keeps an undersized tray; it moves up a size |
| No standard size meets the fill limit (new) | 0 | Shown as "fill limit not met" with the largest fitting size |

## Effect of each change

Each step changes one thing, so every difference has one cause.

| Step | Change | Trays whose size changed |
| --- | --- | --- |
| A → B | Side clearance on both rails | 251 of 1000 (always wider or equal) |
| B → C | Next standard size until fill passes | 9 of 1000 (always larger or equal) |
| C → D | New layer arrangement (multi-layer trays only) | 154 of 600 smaller, 0 larger |

A = legacy engine as today. B = legacy layer arrangement with clearance on both sides and the old selection
(first fit, no upsizing). C = legacy arrangement with all approved rules. D = new engine.

## Smaller cross-section, but wider

The new engine aims for the smallest cross-section (decision D3). Of the 154 multi-layer
trays where it found a smaller tray, 123 are also the same width or narrower, and
31 are wider but shallower (for example 900 × 75 instead of 600 × 150). If width
matters more than cross-section on your projects, the arrangement goal can put width first instead.

| Tray | C: legacy layers | D: new engine |
| --- | --- | --- |
